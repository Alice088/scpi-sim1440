## 2. Функциональное назначение

Программа эмулирует стендовую аппаратуру (SCPI-приборы) и предназначена для:

- разработки и отладки ПО управления испытательным стендом без физических приборов;
- воспроизведения типовых искажений канала связи «оператор — прибор»;
- воспроизведения искажений данных измерения (задержка, подмена, усечение, подавление, разрыв);
- детерминированного воспроизведения сценариев помех для повторяемого тестирования;
- ускоренного проигрывания модели поведения прибора (например, разряда аккумуляторной батареи).

## 3. Описание логической структуры

### 3.1. Архитектура

Программа построена по слоистой схеме. Обработка команды последовательно проходит слои транспорта, менеджера помех и прибора; контрактом прибора является интерфейс `core.Device`.

```
+-------------------------------------------------------------+
|                        Оператор / ПО стенда                 |
+-------------------------------------------------------------+
                              |  TCP, порт 5025, строки \n
                              v
+-------------------------------------------------------------+
| cmd/manager  (оркестратор, вне цикла обработки)             |
|  -action up|down|work -> Docker: образ, сеть stand,          |
|  контейнеры приборов, IP 172.30.0.11+                        |
+-------------------------------------------------------------+
                              |  запускает контейнер
                              v
+-------------------------------------------------------------+
| cmd/scpi-sim1440  (процесс прибора)                         |
|  flag -devindex; config/devices.yaml; net.Listen(tcp)        |
|  горутина модельного времени: Tick(1s * time_scale)          |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
| internal/netx/handlers  (транспорт)                          |
|  VISAHandler.Handle(conn): чтение строк, таймаут 5 мин,      |
|  применение EffectPlan, запись ответа                        |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
| internal/noise  (менеджер помех)                             |
|  Manager.Plan() -> EffectPlan {Device[], Conn[]}             |
|  режимы: always / on_command / after_time / chance; seed     |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
| internal/device  (прибор)          <-- internal/factory      |
|  BAT: MEAS:CHARGE?, MEAS:VOLT?, MEAS:CURR?, *IDN?, *RST      |
|  контракт: internal/core.Device                              |
+-------------------------------------------------------------+
```

Слои и их зависимости:

| Слой | Пакет | Роль | Зависимости |
|---|---|---|---|
| Транспорт | `internal/netx/handlers` | приём соединений и команд, применение эффектов, отправка ответа | `internal/core`, `internal/noise` |
| Помехи | `internal/noise` | планирование эффектов, детерминированный розыгрыш | стандартная библиотека |
| Прибор | `internal/device` | реализация поведения прибора | `internal/core`, `pkg/physic` |
| Фабрика | `internal/factory` | выбор реализации прибора по типу | `internal/device`, `internal/parser` |
| Конфигурация | `internal/parser` | чтение `config/devices.yaml` | `internal/device`, `internal/noise` |
| Ядро | `internal/core` | контракт прибора и типы ответов | стандартная библиотека |
| Физические величины | `pkg/physic` | типы-алиасы единиц измерения | стандартная библиотека |
| Оркестратор | `cmd/manager` | жизненный цикл стенда в Docker | `internal/parser`, Docker SDK |

Направление зависимостей — сверху вниз; пакеты `internal/core`, `internal/noise`, `internal/parser`, `pkg/physic` не зависят от транспорта и оркестратора.

### 3.2. Контракт прибора `core.Device`

Все приборы реализуют единый интерфейс:

```
type Device interface {
    Status() DeviceStatus
    Handle(string) DeviceResponse
    Tick(time.Duration)
    Reset()
}
```

| Элемент | Назначение |
|---|---|
| `Status() DeviceStatus` | текущее состояние прибора: `idle`, `busy`, `fault` |
| `Handle(string) DeviceResponse` | обработка одной команды, возврат значения или ошибки |
| `Tick(time.Duration)` | продвижение модели прибора на интервал модельного времени |
| `Reset()` | приведение прибора к исходному состоянию |

Типы ядра:

| Тип | Состав | Значение |
|---|---|---|
| `DeviceResponse` | `Error error`, `Value string` | результат обработки команды |
| `DeviceStatus` | `idle`, `busy`, `fault` | состояние прибора |
| `DeviceResponseType` | `OK` | константа успешного ответа на команду сброса |

Состояние `busy` и `fault` объявлены в контракте, но в версии 0.1 прибор `BAT` не выполняет переходов в эти состояния: состояние остаётся `idle`, а `Reset()` его подтверждает. Расширение набора состояний выполняется при добавлении новых типов приборов.

### 3.3. Цепочки эффектов `EffectPlan`

Менеджер помех на каждую команду формирует план эффектов:

```
type EffectPlan struct {
    Device []DevEffect   // применяются к прибору
    Conn   []ConnEffect  // применяются к соединению
}
```

Пять типов искажений:

| Тип | Цепочка | Параметр | Наблюдаемый эффект |
|---|---|---|---|
| `delay` | Device | `value` (длительность) | ответ задерживается на заданное время |
| `garbage` | Device | — | значение ответа заменяется на `\ufffd#@%$` |
| `truncate` | Conn | `cut_at` (число символов) | значение обрезается до `cut_at` символов |
| `break` | Conn | — | после записи ответа соединение закрывается |
| `silence` | Conn | — | ответ не записывается, соединение остаётся открытым |

Порядок применения фиксирован кодом обработчика:

| Цепочка | Порядок |
|---|---|
| Device | `delay` → `garbage` |
| Conn | `truncate` → `break` → `silence` |

Совместное действие: если в цепочке соединения присутствует `silence`, ответ не записывается, но остальные эффекты выполняются (задержка и подмена значения отрабатывают). Если присутствуют `truncate` и `break`, записывается усечённое значение, после чего соединение закрывается.

Четыре режима срабатывания каждого искажения:

| Режим | Условие срабатывания |
|---|---|
| пустое значение | искажение отключено |
| `always` | всегда |
| `on_command` | номер команды в соединении равен `n` |
| `after_time` | с момента создания менеджера помех прошло больше `t` |
| `chance` | детерминированный розыгрыш дал значение меньше `chance` |

Детерминированный розыгрыш выполняется по значению `seed`, номеру команды и имени эффекта: вычисляется хеш FNV-1a от строки `seed:cmdCount:effect`, результат нормируется в диапазон `[0, 1)`. При одинаковых `seed`, конфигурации и последовательности команд результат воспроизводится. В версии 0.1 имя эффекта при разборе YAML не заполняется, поэтому все вероятностные искажения одного прибора на одной и той же команде получают одинаковый результат розыгрыша и сравниваются с собственными порогами `chance`.

История сработавших воздействий накапливается в памяти менеджера: для каждой команды, вызвавшей хотя бы один эффект, сохраняется номер команды и применённый план.

Счётчик команд и время старта ведутся в одном экземпляре менеджера помех на процесс прибора. Менеджер создаётся один раз при запуске процесса и используется всеми соединениями; таким образом, номер команды `on_command` и интервал `after_time` отсчитываются по всем соединениям прибора суммарно.

### 3.4. Описание компонентов по пакетам

#### 3.4.1. Пакет `internal/core`

Определяет контракт прибора (`Device`), результат обработки команды (`DeviceResponse`), состояние прибора (`DeviceStatus`) и константу `OK`. Зависимостей от других пакетов проекта не имеет.

#### 3.4.2. Пакет `pkg/physic`

Определяет типы-алиасы физических величин: `Ampere`, `Volt`, `AmpereHour` (все — `float64`). Используется для читаемости конфигурации прибора.

#### 3.4.3. Пакет `internal/device`

Реализует приборы. В версии 0.1 реализован прибор `BAT` (аккумуляторная батарея) и общий обработчик стандартных команд.

Прибор `BAT` хранит имя, команды, состояние, заряд, ёмкость, уровни пустого и полного напряжения, текущее напряжение и ток разряда. Доступ к состоянию защищён мьютексом.

Модель поведения:

| Операция | Формула |
|---|---|
| Начальное состояние | заряд равен ёмкости, состояние `idle` |
| Разряд за тик | `charge = charge - draw × dt.часы`, ограничение снизу нулём |
| Напряжение | `volt = empty_level + (charge / capacity) × (full_level - empty_level)` |
| Ток | равен заданному току разряда `draw` |
| Сброс | заряд равен ёмкости, состояние `idle` |

Числовые ответы формируются с двумя знаками после запятой. Начальное значение напряжения вычисляется один раз при создании прибора и сохраняется в поле прибора (в текущей версии поле не участвует в выдаче ответа — ответ рассчитывается по текущему заряду).

Таблица команд прибора `BAT` (версия 0.1; перечень расширяется):

| Команда | Обработчик | Ответ |
|---|---|---|
| `*IDN?` | общий обработчик | имя прибора, например `bat-1` |
| `*RST` | общий обработчик | `OK`, прибор сбрасывается; режимы помех при этом не прекращаются |
| `MEAS:CHARGE?` | `BAT.Charge` | остаточный заряд, 2 знака |
| `MEAS:VOLT?` | `BAT.Volt` | напряжение, 2 знака |
| `MEAS:CURR?` | `BAT.Curr` | ток разряда, 2 знака |
| любая иная | — | ошибка «unknown command», в линию передаётся пустая строка |

Общий обработчик (`default_handler.go`) обслуживает команды `*RST` и `*IDN?` для любого прибора; остальные команды передаются в карту команд конкретного прибора.

#### 3.4.4. Пакет `internal/factory`

Функция `DeviceFactory` по полю `type` конфигурации выбирает реализацию прибора. Поддерживается тип `bat`. Для неизвестного типа возвращается ошибка `unknown device: <type>`. Для типа `bat` параметры из секции `params` декодируются в структуру `BATConf`; при некорректных параметрах возвращается ошибка декодирования.

#### 3.4.5. Пакет `internal/parser`

Читает YAML-файл конфигурации и возвращает список приборов. Структуры:

| Тип | Назначение |
|---|---|
| `Config` | корневой документ, поле `devices` |
| `RawDevice` | описание одного прибора: `name`, `type`, `addr`, `time_scale`, `noise`, `params` |
| `RawDevice.BATConf()` | декодирование секции `params` в конфигурацию АКБ |

Ошибки чтения и разбора файла возвращаются с контекстом (`read config`, `parse config`).

#### 3.4.6. Пакет `internal/noise`

Реализует менеджер помех: конфигурацию помех (`Conf`), отдельные конфигурации эффектов (`EffectConf`, `DelayConf`, `TruncateConf`), планирование эффектов (`Manager.Plan`), проверку условий срабатывания (`Manager.triggered`) и детерминированный розыгрыш (`Manager.roll`). Разбор секции `noise` из YAML выполняет `Conf.UnmarshalYAML`, длительности разбираются функцией `parseDur` в формате Go (`ms`, `s`, `m`).

#### 3.4.7. Пакет `internal/netx/handlers`

Реализует обработчик соединения `VISAHandler`. Хранит указатель на менеджер помех и прибор. Обрабатывает соединение в цикле: устанавливает таймаут неактивности 5 минут, читает очередную строку, снимает завершающий пробельный символ, запрашивает план эффектов, обрабатывает команду прибором, применяет цепочки эффектов, записывает ответ с завершающим `\n` и при эффекте `break` завершает соединение. Ошибка записи журналируется, обработка соединения продолжается.

#### 3.4.8. Программа `cmd/scpi-sim1440`

Точка входа процесса прибора. Последовательность работы:

1. Разбор флага `-devindex` (индекс прибора в конфигурации, по умолчанию 0).
2. Чтение `config/devices.yaml`.
3. Проверка допустимости индекса: при выходе за границы — аварийное завершение с сообщением.
4. Открытие слушающего TCP-сокета на адресе `addr` выбранного прибора.
5. Создание прибора через `DeviceFactory`.
6. Создание менеджера помех и обработчика соединений.
7. Запуск горутины модельного времени: каждую секунду вызывается `Tick(1s × time_scale)`.
8. Ожидание сигналов `SIGINT`/`SIGTERM` для корректного завершения и закрытия сокета.
9. Приём соединений; каждое соединение обрабатывается отдельной горутиной.

#### 3.4.9. Программа `cmd/manager`

Точка входа оркестратора стенда. Флаг `-action` принимает значения `up`, `down`, `work` (по умолчанию `up`).

| Действие | Последовательность |
|---|---|
| `up` | сборка образа `standemu` из текущего каталога → чтение конфигурации → создание сети `stand` → создание и запуск контейнеров приборов → проверка IP → вывод сводки |
| `down` | чтение конфигурации → остановка контейнеров приборов → удаление сети `stand` → вывод сводки |
| `work` | запуск контейнера `busybox` в сети `stand` в интерактивном режиме с подсказкой о вызове прибора |

Параметры оркестратора:

| Параметр | Значение |
|---|---|
| Имя образа | `standemu` |
| Имя сети | `stand` |
| Драйвер сети | `bridge` |
| Подсеть | `172.30.0.0/24` |
| Первый адрес прибора | `172.30.0.11`, далее последовательно |
| Порт приборов | `5025` |
| Имя контейнера прибора | равно полю `name` прибора |
| Автоудаление контейнера | включено |
| Аргументы контейнера | `-devindex <индекс прибора>` |

### 3.5. Схема цикла обработки команды

```
Клиент (nc / ПО стенда)
   |
   | 1. TCP-соединение на <ip>:5025
   v
cmd/scpi-sim1440: ln.Accept()
   |
   | 2. go visaHandler.Handle(conn)
   v
VISAHandler.Handle
   |
   | 3. SetReadDeadline(now + 5 мин)
   | 4. reader.ReadString('\n')
   | 5. TrimSpace(cmd)
   v
noise.Manager.Plan()
   |
   | 6. cmdCount++; triggered(...) для delay, garbage, truncate, break, silence
   | 7. EffectPlan{Device[], Conn[]}; при наличии эффектов -> history
   v
core.Device.Handle(cmd)
   |
   | 8. defaultHandler: *RST | *IDN?
   | 9. карта команд прибора (BAT): MEAS:CHARGE? | MEAS:VOLT? | MEAS:CURR?
   | 10. иначе -> DeviceResponse{Error: "unknown command", Value: ""}
   v
Применение EffectPlan.Device
   |
   | 11. delay  -> time.Sleep(value)
   | 12. garbage -> Value = "\ufffd#@%$"
   v
Применение EffectPlan.Conn
   |
   | 13. truncate -> Value = Value[:cut_at] (если длина больше cut_at)
   | 14. break    -> пометить закрытие после записи
   | 15. silence  -> пометить подавление записи
   v
conn.Write(Value + "\n")   (если не silence)
   |
   | 16. break -> return (закрытие соединения)
   v
Ожидание следующей команды в том же соединении
```

### 3.6. Схема сборки стенда

```
go run ./cmd/manager -action up
   |
   | 1. docker build -t standemu .
   v
Dockerfile: golang:1.27-alpine -> сборка cmd/scpi-sim1440 -> distroless static-debian12:nonroot
   |
   | 2. parser.Parse("config/devices.yaml")
   | 3. NetworkCreate("stand", bridge, 172.30.0.0/24)   (конфликт игнорируется)
   v
для каждого прибора i = 0..N-1:
   | 4. ContainerInspect(name)
   |      работает        -> пропуск, проверка IP
   |      остановлен      -> удаление и пересоздание
   |      отсутствует     -> создание
   | 5. ContainerCreate(image=standemu, cmd=[-devindex i], AutoRemove)
   | 6. NetworkConnect(stand, IPv4Address = 172.30.0.11 + i)
   | 7. ContainerStart
   | 8. verifyIP: фактический IP контейнера == расчётный
   v
printSummary: "<action>: N devices", для каждого "name ip:5025"
```

### 3.7. Соответствие требованиям технического задания

Требования к системе приведены в документе [tz.md](tz.md) (FR-01 … FR-10, NFR-01 … NFR-03). Реализация версии 0.1 покрывает требования следующим образом.

| Требование | Состояние | Пояснение |
|---|---|---|
| FR-01 | выполнено | контракт `core.Device`; реализация `BAT` не влияет на транспорт и слой помех |
| FR-02 | выполнено частично | адрес и порт берутся из поля `addr`; базовые сетевые константы оркестратора заданы в коде |
| FR-03 | выполнено частично | `*IDN?` и `*RST` есть; `*RST` не сбрасывает слой помех |
| FR-04 | выполнено | один контейнер на прибор, отдельный IP, межприборных каналов нет |
| FR-05 | выполнено | пять искажений реализованы как обёртка, код прибора не меняется |
| FR-06 | выполнено частично | расписание и вероятность — взаимоисключающие режимы; `seed` обеспечивает воспроизводимость |
| FR-07 | выполнено частично | `time_scale` задаёт ускорение; частота шага фиксирована одним шагом в секунду |
| FR-08 | не реализовано | файловый журнал сеанса не ведётся; есть журнал процесса и история воздействий в памяти |
| FR-09 | выполнено | отдельная горутина на подключение, состояние прибора общее |
| FR-10 | выполнено | подъём и остановка стенда одной командой по конфигурации |
| NFR-01 | выполнено | разделение модельной и сетевой логики по пакетам |
| NFR-02 | выполнено частично | параметры приборов вынесены в конфигурацию, сетевые константы оркестратора зашиты |
| NFR-03 | выполнено | обрыв подключения не прерывает работу прибора |

## 4. Используемые технические средства

| Средство | Назначение |
|---|---|
| ПК с процессором x86-64 | рабочее место разработчика и оператора |
| Linux | операционная система |
| Docker Engine | сборка образа, запуск контейнеров приборов, управление сетью стенда |
| Go 1.27.1 | сборка программ и запуск тестов |
| TCP-клиент (`nc`, `busybox`) | подача команд прибору |

Программа прибора в контейнере работает от непривилегированного пользователя `nonroot` на базовом образе `gcr.io/distroless/static-debian12:nonroot`. Образ прибора собирается двухстадийно: сборка в `golang:1.27-alpine`, исполнение в distroless.

## 5. Вызов и загрузка

### 5.1. Запуск стенда

Из корня репозитория:

```
go run ./cmd/manager -action up
```

Команда собирает образ `standemu`, создаёт сеть `stand`, запускает контейнеры приборов и выводит сводку с адресами.

### 5.2. Остановка стенда

```
go run ./cmd/manager -action down
```

### 5.3. Интерактивная оболочка в сети стенда

```
go run ./cmd/manager -action work
```

### 5.4. Запуск эмулятора прибора вне оркестратора

```
go run ./cmd/scpi-sim1440 -devindex 0
```

Флаг `-devindex` задаёт индекс прибора в `config/devices.yaml` (по умолчанию 0). Процесс читает конфигурацию относительно текущего каталога, поэтому запуск выполняется из корня репозитория. Перечень флагов запуска приведён в таблице:

| Программа | Флаг | Значение по умолчанию | Назначение |
|---|---|---|---|
| `cmd/manager` | `-action` | `up` | действие: `up`, `down`, `work` |
| `cmd/scpi-sim1440` | `-devindex` | `0` | индекс прибора в конфигурации |

Подробные сведения о запуске и примеры сеансов приведены в руководстве оператора [rukovodstvo_operatora.md](rukovodstvo_operatora.md).

## 6. Входные данные

### 6.1. Конфигурационный файл `config/devices.yaml`

Входными данными программы является YAML-файл `config/devices.yaml`. Корневой элемент — `devices`, содержащий список приборов.

Полное описание полей:

| Поле | Тип | Обязательность | Назначение |
|---|---|---|---|
| `devices` | список | да | перечень приборов стенда |
| `devices[].name` | строка | да | имя прибора; используется как имя контейнера и как ответ на `*IDN?` |
| `devices[].type` | строка | да | тип прибора; поддерживается `bat` |
| `devices[].addr` | строка | да | адрес прослушивания TCP внутри контейнера, например `:5025` |
| `devices[].time_scale` | число | да | коэффициент модельного времени: сколько секунд модельного времени соответствует одному тику (одной секунде реального времени); дробная часть отбрасывается |
| `devices[].noise` | объект | нет | параметры помех; при отсутствии искажения отключены |
| `devices[].noise.seed` | целое | нет | зерно детерминированного розыгрыша режима `chance` |
| `devices[].noise.delay.mode` | строка | нет | режим срабатывания задержки |
| `devices[].noise.delay.n` | целое | нет | номер команды для режима `on_command` |
| `devices[].noise.delay.t` | длительность | нет | интервал для режима `after_time`, формат Go (`100ms`, `5s`, `1m`) |
| `devices[].noise.delay.chance` | число | нет | вероятность для режима `chance`, от 0 до 1 |
| `devices[].noise.delay.value` | длительность | нет | величина задержки ответа |
| `devices[].noise.truncate.mode` | строка | нет | режим срабатывания усечения |
| `devices[].noise.truncate.n` | целое | нет | номер команды для режима `on_command` |
| `devices[].noise.truncate.t` | длительность | нет | интервал для режима `after_time` |
| `devices[].noise.truncate.chance` | число | нет | вероятность для режима `chance` |
| `devices[].noise.truncate.cut_at` | целое | нет | число символов, до которого обрезается ответ |
| `devices[].noise.garbage.mode` | строка | нет | режим срабатывания подмены значения |
| `devices[].noise.garbage.n` | целое | нет | номер команды для режима `on_command` |
| `devices[].noise.garbage.t` | длительность | нет | интервал для режима `after_time` |
| `devices[].noise.garbage.chance` | число | нет | вероятность для режима `chance` |
| `devices[].noise.silence.mode` | строка | нет | режим срабатывания подавления ответа |
| `devices[].noise.silence.n` | целое | нет | номер команды для режима `on_command` |
| `devices[].noise.silence.t` | длительность | нет | интервал для режима `after_time` |
| `devices[].noise.silence.chance` | число | нет | вероятность для режима `chance` |
| `devices[].noise.break.mode` | строка | нет | режим срабатывания разрыва соединения |
| `devices[].noise.break.n` | целое | нет | номер команды для режима `on_command` |
| `devices[].noise.break.t` | длительность | нет | интервал для режима `after_time` |
| `devices[].noise.break.chance` | число | нет | вероятность для режима `chance` |
| `devices[].params` | объект | да для `bat` | параметры прибора, зависящие от типа |
| `devices[].params.capacity` | число | да для `bat` | ёмкость батареи, А·ч |
| `devices[].params.empty_level` | число | да для `bat` | напряжение при нулевом заряде, В |
| `devices[].params.full_level` | число | да для `bat` | напряжение при полном заряде, В |
| `devices[].params.draw` | число | да для `bat` | ток разряда, А |

Поля `n`, `t`, `chance` относятся к соответствующим режимам `on_command`, `after_time`, `chance`; для неиспользуемых режимов поля можно не задавать. Поле `mode` может принимать значения `always`, `on_command`, `after_time`, `chance`; пустое значение отключает искажение.

### 6.2. Пример конфигурации

Файл `config/devices.yaml`, входящий в поставку версии 0.1:

```yaml
devices:
  - name: bat-1
    type: bat
    addr: ":5025"
    time_scale: 60
    noise:
      seed: 1440
      delay:
        mode: always
        value: 100ms
      garbage:
        mode: chance
        chance: 0.05
      silence:
        mode: chance
        chance: 0.05
      break:
        mode: on_command
        n: 30
      truncate:
        mode: chance
        chance: 0.05
        cut_at: 5
    params:
      capacity: 2
      empty_level: 3
      full_level: 4.2
      draw: 1
```

Конфигурация означает: один прибор `bat-1` (АКБ), прослушивание порта 5025, ускорение модельного времени 60:1, задержка ответа 100 мс на каждую команду, вероятность подмены значения 0,05, вероятность подавления ответа 0,05, вероятность усечения ответа до 5 символов 0,05, разрыв соединения на 30-й команде. При данной конфигурации остаточный заряд уменьшается на 1 А·ч за один час модельного времени (около 60 с реального времени), начальный заряд равен 2 А·ч, начальное напряжение 4,20 В, полный разряд занимает около 120 с реального времени.

### 6.3. Данные, не являющиеся входными

Прочие данные (номера команд, таймауты, адреса) задаются программно и не являются входными данными программы.

## 7. Выходные данные

| Вид | Состав |
|---|---|
| Ответы приборов | строки в TCP-соединение: значения измерений, `OK`, имя прибора, пустая строка для неизвестной команды; при подавлении ответа запись не выполняется |
| Вывод оркестратора | журнал в стандартный поток ошибок: сборка образа, создание сети и контейнеров, пропуск работающих контейнеров, сводка `<action>: N devices` и строки `name ip:5025` |
| Вывод эмулятора прибора | журнал в стандартный поток ошибок: `tcp up`, ошибки `accept`, ошибки записи ответа, ошибки расчёта вероятности |
| Состояние Docker | образ `standemu`, сеть `stand`, контейнеры приборов с фиксированными IP-адресами |
| Файлы | программа не создаёт файлов; требование FR-08 о записи журнала сеанса в файл в версии 0.1 не реализовано, журналы доступны только в потоке вывода процесса |
