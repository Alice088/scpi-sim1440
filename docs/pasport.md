## 2. Назначение и область применения

### 2.1. Назначение

Программа предназначена для эмуляции стендовой аппаратуры (SCPI-приборов) при разработке и отладке ПО управления испытательным стендом. Программа принимает команды по TCP, формирует ответы прибора и вносит управляемые искажения канала связи и результатов измерений.

### 2.2. Область применения

| Аспект | Значение |
|---|---|
| Область применения | разработка, отладка и автотестирование ПО управления испытательным стендом |
| Категория пользователей | разработчики и операторы испытательного стенда |
| Условия применения | локальное рабочее место с Docker и Linux |
| Ограничение применения | программа является учебным проектом и не предназначена для применения в составе реальных испытательных стендов и в качестве средства измерений |

## 3. Основные технические показатели и условия применения

### 3.1. Функциональные возможности

| Возможность | Значение |
|---|---|
| Протокол управления | TCP, текстовые SCPI-подобные команды, разделитель строк `\n` |
| Порт приборов | 5025 |
| Число приборов | определяется конфигурацией `config/devices.yaml`; в поставке — один прибор `bat-1` |
| Типы приборов | тип реализации задаётся конфигурацией; в поставке — `bat` (аккумуляторная батарея); перечень расширяется |
| Команды прибора `bat` | `*IDN?`, `*RST`, `MEAS:CHARGE?`, `MEAS:VOLT?`, `MEAS:CURR?`; служебные команды обязательны для любого прибора (FR-03), состав измерительных команд определяется реализацией (FR-01) |
| Искажения канала | `delay`, `garbage`, `truncate`, `silence`, `break` |
| Режимы искажений | `always`, `on_command`, `after_time`, `chance` |
| Детерминированность | воспроизводится по полю `seed` |
| Модельное время | ускорение относительно реального времени по полю `time_scale` |
| Параллельные подключения | не ограничены программно; каждое соединение обрабатывается отдельно |
| Таймаут неактивного соединения | 5 минут |
| Журналирование | требование FR-08: журнал сеанса в файл на приборе; в версии 0.1 не реализовано — доступны журнал процесса (стандартный вывод) и история сработавших воздействий в памяти |

### 3.2. Требования к среде

| Компонент | Требование |
|---|---|
| Операционная система | Linux |
| Среда контейнеризации | Docker Engine |
| Go | 1.27.1 или совместимая версия (для сборки и запуска из исходного кода) |
| Процессор | x86-64 |
| Оперативная память | 512 МБ, доступных Docker |
| Дисковое пространство | 1 ГБ |
| Сеть | подсеть `172.30.0.0/24` доступна, порт TCP 5025 не занят |
| Внешние зависимости | `github.com/docker/docker v28.5.2`, `gopkg.in/yaml.v3 v3.0.1` |
| Базовый образ контейнера прибора | `gcr.io/distroless/static-debian12:nonroot` |

### 3.3. Степень соответствия техническому заданию

Реализация версии 0.1 соответствует требованиям FR-01, FR-02, FR-04, FR-05, FR-09, FR-10, NFR-01, NFR-03 полностью (FR-02 — с примечанием о не-ASCII мусорных данных, раздел 9 документа [tz.md](tz.md)). Требования FR-03, FR-06, FR-07, NFR-02 выполнены частично (подробности — в разделе 9 документа [tz.md](tz.md) и в разделе 3.7 документа [opisanie.md](README.md)). Требование FR-08 (журнал сеанса в файл) не реализовано. Требований, не вошедших ни в одну категорию, нет.

### 3.4. Показатели надёжности

| Показатель | Значение |
|---|---|
| Устойчивость к некорректной команде | неизвестная команда возвращает пустую строку, соединение не разрывается |
| Устойчивость к повторному запуску | повторный запуск стенда не приводит к ошибке |
| Устойчивость к отсутствующим сущностям Docker | отсутствие контейнера или сети при остановке игнорируется |
| Защита состояния прибора | доступ к состоянию синхронизирован мьютексом |
| Корректное завершение | по сигналам `SIGINT` и `SIGTERM` |

## 5. Порядок установки и вызова

### 5.1. Установка

Установка выполняется получением исходного кода программы и подготовкой рабочего места: установка Docker Engine, установка Go 1.27.1, переход в корень репозитория. Отдельная процедура инсталляции не требуется: образ прибора собирается автоматически при запуске стенда.

### 5.2. Вызов программы

Одна команда запускает весь стенд (сборка образа, создание сети, запуск контейнеров приборов):

```
go run ./cmd/manager -action up
```

Дополнительные действия:

| Команда | Назначение |
|---|---|
| `go run ./cmd/manager -action up` | запуск стенда |
| `go run ./cmd/manager -action down` | остановка стенда и удаление сети |
| `go run ./cmd/manager -action work` | интерактивная оболочка в сети стенда |
| `go run ./cmd/scpi-sim1440 -devindex 0` | запуск отдельного прибора вне оркестратора |

После запуска стенда прибор доступен по адресу `172.30.0.11:5025`. Порядок работы приведён в руководстве оператора [rukovodstvo_operatora.md](rukovodstvo_operatora.md).
